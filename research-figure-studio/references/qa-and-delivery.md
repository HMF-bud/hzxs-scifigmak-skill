# 合并审核与交付

检查对象是同一次最终导出；不能把源文件、旧预览和新PDF的结果混成通过。先核对科学定义和值，再处理排版；需要修复时改主源并重导，不直接涂改最终数值图像。

## 包内统一PDF检查

```text
python <本包>/scripts/audit_figure.py <最终单图.pdf> --panels 4 --layout <最终alignment.json> --out <项目>/checks/final --min-pt 5
```

这是本包内脚本，直接调用同目录PDF文字、碰撞和对齐检查器；不定位或调用外部nature-figure目录。读取PDF需PyMuPDF，缺依赖返回未验证而非通过；使用已有环境，安装需按实际权限处理。

- panels指被测量的绘图区数量；若一个科学子图含过程轴和误差轴，分别测量，和实际manifest一致。色标、图例轴是否排除需记录。
- layout来自最终画布的真实几何，含figure尺寸、panels及可比组。无manifest的多面板图为NOT_AUDITABLE。技术对齐容差沿用1.5pt，非等宽设计记录具体例外，不放宽全局阈值。
- 同一PDF只运行一次合并检查；对齐阶段已测量，最终PDF尺寸绑定确保导出没有变画布。修复后针对新导出重查受影响项，保留原报告。
- 源码检查可用`python <本包>/scripts/validate_figure.py <实际绘图脚本> --json`。静态规则是预检，动态宽度、共享样式、非请求格式等需结合实际输出说明；不要修改科学图去盲从误报。

| 状态 | 处理 |
|---|---|
| PASS | 自动项通过；仍须看最终图与核对统计语义 |
| REVIEW_REQUIRED | 查看具体警告，修复或记录合理例外 |
| FIX_REQUIRED | 修源、重导并复查，不能称已通过 |
| NOT_AUDITABLE | 补缺失依赖/几何/可读文件，无法补齐时明确未验证 |

draw.io/纯SVG另使用[method-figures.md](method-figures.md)的结构和几何检查。同一问题不因多个来源规则重复执行；结构、字体、碰撞属于不同检查，可以组合。QA叠图仅供检查，不替换投稿文件。

## 实际渲染与内容核对

分别查看最终PNG和PDF实际渲染，在论文尺寸判断：

1. 比较对象、样本、分母、单位、符号、配对与聚合顺序、区间定义和实际值对应源表。
2. 面板主次与面积合理，读者能识别编码；核心数字清楚，删掉数字后的空白已相应压缩。
3. 图例、色标跟随所属面板；符号/颜色/线型吻合，不遮挡或跨无关面板。
4. 字号、刻度、箭头、误差线、近零值、零线、边界完整，无裁切。公式上下标也检查实际字号。
5. 方法图逐边核对科学关系；多图总览页数、顺序与指定更新范围一致，未改图沿用既有验收。

对重新设计的数据图，在投稿宽度下先遮住源表和工作日志，用最终图与图注逐一回答方案中约定的读图问题，再用源表核对答案。选一个普通组合或有区分力的反例，记下从哪个面板、标记或数字读出；留意是否必须跨远处查表或心算。联合计数须能追到配对分类，幅度须能追到相应单位和统计层级。验读与自动排版结果分开记录。缺少约定答案时修正选定方案内的编码；用户已明确接受的取舍按其决定保留。只移动图例等局部修改时，复查被改动的读法即可。

无法看图就明确未完成视觉检查；自动工具不证明科学结论或审美。碰撞层含不可见裁剪对象时保留原失败报告，用真实渲染与可审查对象解释，不改成假PASS。只对实际变化做必要核对，不重复全目录哈希或无关测试。

## 交付与维护

按用户要求交付PNG/PDF/SVG或原生draw.io、实际使用代码、运行说明、必要数值核对和精简图注。图注定义读法，工作日志记录执行和检查。原图、原数据、共享配置不改；输出另存版本。不得自动新增PPT、Word、补充图、压缩包或对外发送。

三类记录放在既有工作日志：本轮修改；本项目已接受约定；明确授权维护的通用偏好。本包与原技能分别保留，用户要求同步时以[来源说明](provenance.md)和[文件清单](../origin_manifest.json)定位来源，只合并相关变化，不全量覆盖本包的后续决定。
